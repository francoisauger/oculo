# Oculo

Oculo is a thin, rebranded fork of [SmartTube](https://github.com/yuliskov/SmartTube) by yuliskov (MIT),
built for Android TV / Google TV. It installs next to the official SmartTube (different package name).
Oculo is not affiliated with YouTube or Google.

## Branches and remotes

- `upstream` = https://github.com/yuliskov/SmartTube (its default branch is `master`).
- `main` tracks `upstream/master` and is never edited.
- `oculo` = `main` + the Oculo changes below. Build from here.

## What the fork changes

Kept untouched: `MediaServiceCore`, `SharedModules` (submodules), `exoplayer-amzn-2.10.6` and `chatkit`.

**MediaServiceCore pin (32.74-10).** Oculo pins `MediaServiceCore` to upstream commit `767a6685` instead of 32.74's `b3d561f5` (both upstream, no Oculo edit). From `66b5a1bc` on (SmartTube 32.73 and 32.74), `FormatInfoWrapper.CLIENT_LIST` starts with the WEB client (Innertube); its WebView poToken is not accepted by the SABR server (`StreamProtectionStatus` stays `ATTESTATION_PENDING`), so YouTube serves about 60 s and then no more media: every video stalls at 0:59 (upstream issues #6370, #6461, #6463, #6439). `767a6685` is the same code with the TV client first, as in 32.71. It lacks two small upstream changes: the "fallback to error result" for unplayable videos and the per-client nonce reset (`b3d561f5`, only matters when a client falls through to the next). After a merge with upstream, move the pin back to upstream's only once upstream fixes the WEB attestation or puts TV first again.

## Settings

Since 0.11.0 (`docs/mockups/settings/settings-redesign.html`, approved whole by François on 16 Nov. 2026).

**How it works.** Upstream's 13 presenters stay as they are. `OculoSettingsModel` reads what each would show
(`OculoSettingsCapture`: while it runs, `AppDialogPresenter.showDialog()` hands over its categories instead of showing
them; buttons that only open a sub-screen, « Screen dimming », « Network », « Video speed », « Google Drive », are read the
same way), then `OculoSettingsMap` places each upstream setting by its title (upstream string resource, so any language;
literal titles for the untranslated key remapping items). The rows hold upstream's own `OptionItem`s, wrapped only to
rename them (`OculoOptionItem`), so selecting a value runs upstream's callback: same preferences, same side effects, same
« restart the app » notices (upstream's « on close » callbacks run when leaving the Settings section). Nothing is migrated.
The model is rebuilt after each change (shortly after, about 30 to 100 ms on the emulator) to refresh every value.

**Tree.** Seven categories, in this order, plus « Advanced » in advanced mode:

| Category | Simple mode (default) | Advanced mode adds (under an « Advanced » heading) |
|---|---|---|
| Playback / Lecture | When a video ends, Video quality (Auto + one value per resolution), Speed, Skip step, Pause when idle (upstream's « Sleep timer », renamed in 0.13.0), Pause screen (0.14.0, Oculo's own) | Background playback, speed memory, More speeds (Short / Long / Extra long), buffer, picture fit, seeking, live edge, resume, playlist and Shorts behaviour, « Player screen » (player buttons, clocks, suggestions, tooltips…), « Frame rate » (AFR) |
| Audio & Subtitles / Son et sous-titres | Audio language, Subtitle style, Subtitle size | Subtitle position, per-channel subtitles, audio delay, volume boost, audio focus, loudness, time stretching |
| Home & Display / Accueil et affichage | Start screen, Sidebar sections, Dim the screen after, Interface size, Hide news and sports rows, Show Continue watching | Oculo's Home options, Theme, card size and style, clock, dimming level, screensaver, long-press menu, channels and playlists layout |
| Account & History / Compte et historique | Account (switch, add, sign out: upstream's account screen), YouTube language, Content country, Watch history, Search history | Pause history while casting, separate settings per account, ask which account at start, account / settings / master password, child mode, import subscriptions |
| SponsorBlock & Filters / SponsorBlock et filtres | Hide Shorts everywhere, Hide watched videos in Subscriptions (0.13.0), SponsorBlock, Segments | progress bar markers, short segments, notices, server links, Hide Mixes / live / watched (Home, Watch later, notifications), « Hide Shorts in… », « Hide upcoming in… », original titles, DeArrow, thumbnail frame |
| Remote & Devices / Télécommande et appareils | Phone remote, Link a phone | cast list, unlink phones, close on disconnect, Back button rules, OK button, number keys, « Button shortcuts » (key remapping), keyboard and voice |

## Typography

Rule approved by François (0.10.0, 15 Nov. 2026). New screens follow it.

| Text type | Font |
|---|---|
| Titles and short labels: card titles, row titles (« Recommended »), left rail items, buttons, a video's title, dialog and panel titles | Roboto Condensed (`sans-serif-condensed`, leanback's `TextAppearance.Leanback`), kept as upstream |
| Sentences and paragraphs: video description, comments, empty and error state explanations, settings summaries, sign-in steps, any multi-line prose | Roboto Regular (`sans-serif`); long prose with the comments' line spacing, `lineSpacingMultiplier` 1.28, at 16sp |

Where it is applied: `smarttubetv/src/oculo/res/values/oculo_typography.xml` (`OculoParagraphText` for dialog messages
such as the video description, `OculoSummaryText` for settings summaries, `TextAppearance.Leanback.ImageCardView.Content`

upstream look of the two Oculo styles for the other flavors. Comments: `layout/oculo_comment_item.xml` (sans-serif, 1.28,

## Signing

The release key is never in the repo. `oculo.gradle` reads a JSON file
(`storeFile`, `storePassword`, `keyAlias`, `keyPassword`) from `-PoculoSigningConfig=<path>`,
the `OCULO_SIGNING_CONFIG` environment variable, or by default `~/.config/chuck/oculo/signing.json`.
On François's Mac the keystore is `~/.config/chuck/oculo/oculo-release.jks`.
Losing that key means existing installs can no longer be updated in place: keep a backup.

## In-app updates

`update_urls` points to `https://github.com/francoisauger/oculo/releases/latest/download/oculo_stable.json`.
The manifest uses the SmartTube format (`SharedModules/appupdatechecker2/.../AppVersionChecker.java`):

```json
{
  "package": {
    "downloadUrlList": ["https://github.com/francoisauger/oculo/releases/download/<tag>/Oculo_<version>_armeabi-v7a.apk"],
    "downloadUrlList_arm64-v8a": ["https://github.com/francoisauger/oculo/releases/download/<tag>/Oculo_<version>_arm64-v8a.apk"],
    "downloadUrlList_x86": ["https://github.com/francoisauger/oculo/releases/download/<tag>/Oculo_<version>_x86.apk"]
  },
  "0.9.0": { "versionCode": 1009000, "changelog": ["..."] }
}
```

Version keys are versionNames (« 0.9.0 »; the updater never parses them, it only displays the newest one); it
takes the entry with the highest `versionCode`, compares it with the installed one and picks
`downloadUrlList_<primary ABI>`, then `downloadUrlList`, then `downloadUrl`. The primary ABI is
`Build.SUPPORTED_ABIS[0]` (`DeviceHelpers.getPrimaryAbi()`): `armeabi-v7a` on the TCL (32-bit userland), so it gets
`downloadUrlList_armeabi-v7a`. The changelog shown is the concatenation of the `changelog_<language>` (else
`changelog`) arrays of every entry newer than the installed version, newest first.

How it runs (checked on 20 Nov. 2026 on the headless emulator, 0.12.99 test build -> published 0.13.0: check,
download, notice, changelog, Android's install prompt and the update itself; upstream code, nothing Oculo-specific
needed):

- **When**: once per app start (`SplashPresenter.runPerViewTasks()` -> `BootDialogPresenter` ->
  `AppUpdatePresenter.start(false)`, about 10 s after launch), skipped if the last « no update » answer is less
  than 60 s old (`SettingsManager.CHECK_INTERVAL_DEFAULT_MS`); no periodic job.
- **Notice**: Settings › System › About Oculo › « Check for updates automatically »: Disabled, Sidebar notification
  (upstream default, kept: an « Update » section with the info icon pinned at the top of the rail, above Home, showing
  « Oculo <version> Changelog: » and the bullets, with an Install update button) or Dialog notification (the « Update
  available » Oculo panel at start: title « Oculo <version> », Install update, then a Changelog row opening the
  bullets). Settings › System › Check for updates forces a check and always opens that panel.
- **Download**: OkHttp from `SharedModules/sharedutils` (`OkHttpManager`, redirects followed, OkHttp's default), so
  `github.com/.../releases/latest/download/...` -> `github.com/.../releases/download/<tag>/...` ->
  `release-assets.githubusercontent.com` works. The APK goes to the app's internal cache (`update.apk`); a download
  that takes more than 60 s is dropped (`DownloadManager.MAX_DOWN_TIME_MS`, about 4 Mbit/s for a 28 MB APK) and is
  retried at the next start. The downloaded file must be over 1 MB, carry the package `com.francoisauger.oculo` and is
  reused for 15 min.
- **Install**: `Helpers.installPackage()` -> `ACTION_VIEW` on a `FileProvider` URI, authority
  `${applicationId}.update_provider` = `com.francoisauger.oculo.update_provider` (library manifest, merged), with
  `REQUEST_INSTALL_PACKAGES` (library manifest, merged). Android asks once to allow Oculo to install unknown apps,
  then shows its install prompt. The new APK must be signed with the same key (« Signing »).
- **Hosts the TV must reach** (DNS allowlist): `github.com` (manifest and APK URLs, both redirect) and
  `release-assets.githubusercontent.com` (the files). `objects.githubusercontent.com` was GitHub's previous asset
  host: allow it too.

## Releases

Each Oculo version is a GitHub Release `v<version>` on `francoisauger/oculo` (public, approved by François on
20 Nov. 2026), with `Oculo_<version>_{armeabi-v7a,arm64-v8a,x86}.apk`, `oculo_stable.json` and `SHA256SUMS.txt`,
marked latest (that is what `releases/latest/download/oculo_stable.json` follows).

1. Bump `oculoVersion` in `smarttubetv/oculo.gradle` and add a `## <version>` section to `CHANGELOG.md` (short French
   bullets, user-facing: the updater shows them on the TV). Commit, push `oculo`.
2. `scripts/publish-release.sh` (`--dry-run` builds and writes the manifest only). It refuses unless on `oculo`, no
   tracked change, HEAD pushed, submodules at their pins, tag and release absent. It builds `assembleOculoRelease`
   (JDK 17), checks each APK's signer against the keystore's certificate (read in place, never copied) and its
   package / versionCode / versionName, writes the manifest (every CHANGELOG section up to this version, so a TV that
   skipped versions sees all the notes; `downloadUrlList` = armeabi-v7a, `downloadUrlList_x86_64` = x86), creates the
   annotated tag, pushes it, `gh release create --latest`, then downloads `releases/latest/download/oculo_stable.json`
   and every APK it lists (redirects followed, HTTP 200, sha256 equal to the local build) and prints the hosts of
   the redirect chain. Files stay in `smarttubetv/build/oculo-release/v<version>/`.

## Version numbers

Since 0.9.0 (15 Nov. 2026, François's decision of 12 Nov.), Oculo has its own numbers; until then builds were
`32.74-1` to `32.74-21` (upstream versionName + Oculo revision, versionCode = upstream 2464 × 100 + revision).

- One place: `def oculoVersion = '0.14.0'` at the top of `smarttubetv/oculo.gradle`. MAJOR.MINOR.PATCH: 1.0.0 is
  reserved for the public release; MINOR = a new batch of features asked for by François (0.9.0 -> 0.10.0 ->
  0.11.0 -> 0.12.0 -> 0.13.0 -> 0.14.0); PATCH = a rebuild picking up a new upstream SmartTube (0.10.0 -> 0.10.1). Every published build changes it.
- versionName (shown everywhere) = `oculoVersion`; APK names `Oculo_0.9.0_<abi>.apk`.
- versionCode, computed by `oculoVersionCode()` in `oculo.gradle`: 1,000,000 + MAJOR × 1,000,000 + MINOR × 1,000
  + PATCH (0.9.0 = 1009000, 0.10.1 = 1010001, 1.0.0 = 2000000). It grows with the version whatever part changes
  (MINOR and PATCH must stay below 1000; the build fails otherwise), is above every 32.74-N build (246401 to 246421),
  so 0.9.0 installs over 32.74-21, and stays far below Integer.MAX_VALUE. Upstream bumps go through PATCH, so they
  increase it too.
- The SmartTube version Oculo is built on (defaultConfig's versionName, « 32.74 ») is only shown in About:
  « Oculo 0.9.0 · basé sur SmartTube 32.74 » (`common/.../oculo/OculoVersion.java`, `R.string.oculo_upstream_version`
  generated by `resValue` in the flavor, `oculo_about_based_on` EN/FR in common's `oculo.xml`), and in release notes.
- In-app updates compare versionCodes only (see « In-app updates »); `GeneralData`'s stored versionCode (« show the
  changelog after an update ») sees 1009000 > 246421 as an update, as it should.
