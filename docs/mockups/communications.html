Oculo : toutes les communications réseau

Audit du code de la saveur oculo (base F-Droid, sans Firebase), sous-modules compris, le 12 nov. 2026. Chaque carte = une destination que l'appli peut contacter. Coche « Garder » pour ce que tu veux conserver ; les cases sont préremplies selon ma recommandation. Rien n'a été changé dans l'appli.

À retenir

  1. Aucun rapport de plantage, aucun journal, aucune statistique d'usage ne part vers yuliskov ni vers un service de rapports : Crashlytics n'existe que dans les versions officielles, le « journal dans un fichier » reste sur la télé.
  2. Le code d'activation de ton compte YouTube part chez un tiers : l'écran de connexion fabrique son code QR en envoyant l'adresse youtube.com/qr/activate/<code> à api.qrserver.com. Même chose pour « Partager le lien QR » (vidéo + minute) et les liens de l'écran À propos.
  3. Un seul contact automatique vers yuliskov : constants.json sur son GitHub, téléchargé seulement si tu utilises la sauvegarde Google Drive ou l'import de chaînes NewPipe. Il fournit les clés de ses projets Google (Drive et YouTube Data API). La connexion au compte YouTube n'en dépend pas : elle prend les clés de l'appli YouTube TV elle-même.
  4. Deux services tiers sont actifs par défaut à chaque vidéo : SponsorBlock et Return YouTube Dislike reçoivent l'identifiant de la vidéo et ton adresse IP. Les deux se coupent déjà dans les réglages.
Méthode : recherche de toutes les adresses http(s) dans le code, les ressources et Gradle de tous les modules (dont MediaServiceCore, SharedModules, exoplayer-amzn), puis lecture des clients réseau (Retrofit, OkHttp, WebView, téléchargements, intents, sockets). Les démos et tests d'ExoPlayer sont exclus : ils ne font pas partie de l'APK. La note grise en bas de chaque carte indique où se trouve le code.
